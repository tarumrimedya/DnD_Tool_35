## 3. Pure Canonical V3 Data Architecture (`schemaVersion: 3`) & Pluggable Ruleset Contract
- **No Dummy Data:** Query the local Modular Compendium (`database/srd_index.json` + `24` indexed chunks: `23` `srd_*.json` packs + `mic_compendium.json`, `8,007` pure V3 entries including `649` Bestiary, plus `lego_patterns.json`) first; do not scrape `d20srd.org` unless requested.
- **Dynamic Gear Assembly & 3-Layer Copy-on-Write Isolation:** Composite gear (*"+2 Keen Mithral Scimitar"*) assembles dynamically from `baseItemId`, `material`, `enhancementBonus`, and `enhancements[]`. Custom/homebrew and `Rule Crafter` edits live in character-scoped `char.customEntries` (V3 Copy-on-Write overrides), `char.customDb` (`srd-snapshot` & custom entries), or shared `campaign_packs` (`campaign_db.js`) — never pollute `database/*.json` (`master_db.json` is legacy sandbox seed data only).
- **Pure Canonical V3 Contract (`schemaVersion: 3`, Zero Disk V2 in `database/`):**
  1. **Atomic `effects[]` Blocks:** Mechanical rules use `effects[]` (`stat`, `roll`, `attack`, `defense`, `effect` Rule Switches, `resource`, `when`, `table`, `carrier`) + `choices[]` (`@Choice`) across `12` blueprints (`spell`, `feat`, `classAbility`, `monster`, etc.). Legacy `modifiers[]` / `damageParts[]` are banned across `database/*.json` (`migrateEntryToV3` exists solely at the external/legacy import boundary).
  2. **Narrative vs. Mechanical Boundary & Zero Shadow Logic:** Narrative/utility entries (*Teleport*, *Wish*) stay clean metadata + text (`effects: []`); mechanically active classes/variants (`replaces[]`), `cab-*` `ClassAbility` entries, feats, domains, items, and buffs own explicit V3 `effects[]`. Never hardcode duplicate per-feat/per-feature `if` math in `rule_engine.js` or regex-scrape descriptions.
  3. **Immutable `id` References:** Match classes, variants, `cab-*` features, feats, items, and spells by immutable `id` / `baseItemId`, not loose display strings.
  4. **Pluggable System Physics (`RuleEngine.rulesets.<id>`):** Keep the V3 block interpreter system-agnostic and isolate D&D 3.5e core laws (stacking matrix, skill rank cap/cost, iterative BAB, size/grapple math, save progressions) inside `RuleEngine.rulesets.dnd35` so future rulesets (`pf1`, `pf2`) plug in cleanly.
